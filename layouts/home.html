Kuberik is a controller that lives in your cluster. Each environment is a Kubernetes resource that says what a build has to pass there: health checks, a schedule, a dependency, an approval. There is no pipeline to script and no server to run.

Nothing moves before its dependencies.

Say that checkout-api needs payments-svc 3.0. A new checkout-api build then waits in each environment until that payments-svc version is already running there, and goes on by itself once it is. Services that need nothing new are not held.

Install it with Helm.

The controller runs in your cluster, next to the thing it gates. No hosted service, no agent to register.

Terminal
$ helm install kuberik \
    oci://ghcr.io/kuberik/charts/kuberik \
    --namespace kuberik-system \
    --create-namespace \
    --set createNamespace=false
