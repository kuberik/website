A failing check stops the build where it is.

Kuberik reads your metrics after every deploy. When one breaks its budget, the build goes no further, production keeps the last good build, and Roll back is one press away.

How health checks work →

Runs in your cluster, next to Flux.

Install it with one Helm release and keep your GitOps as it is. Kuberik works beside Flux; it does not replace it.

Apache 2.0 · Runs in your cluster · No SaaS

Install
$ flux check
$ helm install kuberik \
    oci://ghcr.io/kuberik/charts/kuberik \
    --namespace kuberik-system \
    --create-namespace \
    --set createNamespace=false

Ship the next build and go do something else.
